# ログと通信障害の調べ方

[README](../README.md)に起動手順、[ログと通信診断の仕様](../openspec/specs/diagnostics/spec.md)に記録の要件をまとめています。

## ログの保存と共有

アプリのログは画面に表示すると同時に、プロジェクトの `logs/` フォルダへUTF-8のテキストで保存します。起動ごとに `udobs-日時-プロセスID.log` を作り、起動時に保存先を表示します。各行の日時はUTCです。

字幕本文、接続・切断、警告、エラー、終了処理のログが保存されます。`Ctrl+C` の直前まで保存するため、書き込みはその都度行います。pnpm自身の `ELIFECYCLE` 表示や、アプリ起動前のビルド出力は含まれません。

ログには会話本文や接続先が含まれます。共有する前に内容を確認してください。`logs/` はGitの管理対象外です。ログは自動削除しないので、不要になったファイルは削除してください。

## UDトークの通信失敗

UDトークとの通信に失敗した場合は、初回から処理名、通信開始から失敗までの時間、エラー名・コード・内部原因も記録します。計測には応答本文の受信・解析も含みます。公開URL、セッショントークン、パスコード、認証トークン、Cookieは診断ログから伏せます。終了操作による通信中断は失敗として記録しません。

```text
UDトーク通信失敗: 処理=web/pull/webTalkMessage, 経過=5002ms, タイムアウト設定=5000ms, 接続タイムアウト設定=2000ms, name=TimeoutError, message=The operation was aborted due to timeout
```

`経過` は実際にかかった時間です。`タイムアウト設定` はこのアプリの通信全体の上限です。通信処理内部の別のタイムアウトや切断により、それより早く失敗する場合もあります。成功したすべての通信について個別の診断ログを出すわけではありません。ソケットの終了は別途記録します。

### Web公開のパスコード認証に失敗する場合

`パスコードが必要です` と表示された場合は、`.env` の `UDTALK_PASSCODES` で該当URLのパスコードを指定するか、共通値の `UDTALK_PASSCODE` を設定して再起動してください。個別値が優先され、空文字の個別値は共通値を使わない指定です。ログの `[Web公開1]` などは重複除去後のURL設定順に対応します。パスコードなしの公開では設定不要です。

`パスコード認証に失敗しました` の場合は公開者にパスコードを確認してください。`Cookieを取得できませんでした` や認証処理のHTTPエラーの場合は、ブラウザーでも公開ページを開けるか確認してください。ブラウザーでは認証できるのにアプリで失敗する場合、閲覧ページの通信方式が変わった可能性があります。Cookieや認証値をログや問い合わせに貼り付けないでください。

### タイムアウトと再試行の設定

`UDTALK_REQUEST_TIMEOUT_MS` はUDトークとの通信全体の上限です。既定は `5000` ミリ秒で、接続待ちから本文の受信・解析までを含みます。TCP・TLSの接続待ちは別に `2000` ミリ秒で打ち切り、接続できない場合の再試行を早めます。通信全体の上限が2秒未満なら、接続待ちにもその短い上限を使います。接続成立後も通信全体の上限は変わらず、接続にかかった時間も含みます。

通信失敗ログには通信全体と接続待ちの両方の上限を記録します。タイマーの実行には多少の遅れが生じる場合があります。遅い正常応答も打ち切る可能性があるため、その場合は `10000` などに上げてください。ただし接続待ちは2秒のままです。UDトーク専用の通信エージェントを使い、終了時にはそのエージェントも破棄します。OBSや他の通信の設定は変更しません。

会話取得や閲覧セッション作成に連続で失敗すると、再試行までの待ち時間を `POLL_MS`、その2倍、4倍と延ばします。上限は `UDTALK_RETRY_MAX_MS` で、既定は `10000` ミリ秒です。例えば `POLL_MS=1000` なら、失敗後の待ち時間は1秒、2秒、4秒、8秒、10秒となります。通信自体にかかった時間は別です。会話取得が成功すると通常間隔に戻ります。

一時的な通信失敗では取得位置を保持し、同じ位置から再試行します。これらは待ち時間と接続負荷を調整する対策で、回線や取得先の障害自体を直すものではありません。CLIでは `--udtalk-request-timeout-ms` と `--udtalk-retry-max-ms` でも指定できます。前者は1〜2147483647、後者は `POLL_MS` 以上かつ2147483647以下の整数を指定してください。

## 接続診断の読み方

失敗時の `接続診断` には、接続先IP、TCP・TLS接続の成立通知と所要時間、接続の再利用、TLSセッション再開、ALPNの結果を記録します。所要時間はソケットの作成を観測してからの時間です。再利用した接続では、最初に接続したときの時間を表示します。診断機能自体は通信方式や待ち時間を変更しません。

成功時の `UDトーク接続診断` は、処理ごとの初回の新規接続・再利用と、失敗後の最初の成功時に出力します。`接続#` が同じなら同じソケットです。接続の再利用とTLSセッション再開は別の情報です。

`TCP=成立` で `TLS=未観測` の場合は、TCP接続後にTLS成立通知を確認できなかったことを示します。`未観測` は失敗の断定ではありません。Node.jsのバージョンや通信方式によって通知が得られない場合もあります。

接続診断には、要求・応答の `Connection` と、応答の `Keep-Alive` の `timeout`・`max` も記録します。応答を受け取ってヘッダーが存在しない場合は `なし`、応答自体を確認できなかった場合は `未観測` です。未知のヘッダー値は伏せ、ヘッダー全体・Cookie・本文・トークンは保存しません。

### ソケットの終了通知

`UDトークソケット終了` は、通信完了後に接続が閉じた場合も記録します。同じ `接続#` の診断と照合してください。`end` は受信側の終了通知、`finish` は送信側の終了通知です。これらだけでは切断の原因を断定できません。

HTTP 200の応答が完了し、`Connection=close` に従って正常に整理した接続は処理ごとに60秒間の件数へ集約します。それ以外の終了は個別に記録します。終了時には残った件数を出力して監視を解除します。

通信ライブラリが正常な接続整理に使う `UND_ERR_INFO` でも、`close.hadError=true` になる場合があります。この組み合わせだけで通信障害とは判断せず、HTTP応答と通信失敗ログも合わせて確認してください。

### 接続タイムアウトの切り分け

`UND_ERR_CONNECT_TIMEOUT` は接続処理のタイムアウトです。まず同じ通信の `接続診断` を確認してください。HTTPヘッダー送信・TCP・TLSがすべて `未観測` なら、HTTP応答の遅延と決めつけず、TCP接続から調べます。ログだけでは通知を取得できなかった可能性も残ります。

パケット取得で、PCからTCP接続要求のSYNを再送してもSYN-ACKが戻らない場合は、TLSやHTTPより前の段階で接続が止まっています。PC側の観測だけでは、要求が途中で失われたのか、接続先が応答しなかったのか、戻りの応答が失われたのかまでは分かりません。

同じPC・アプリのバージョン・設定で、家庭回線とモバイル回線を比較してください。各回でアプリを1つだけ動かします。片方の回線でだけ再現する場合は、ルーター、プロバイダーから接続先までの経路、送信元IPに対する接続先の制限などが候補になります。短時間に再現しなかっただけでは、解消したとは判断できません。

プロバイダーへ相談する場合は、発生日時とタイムゾーン、接続先ホストとポート、エラーコード、別回線との比較結果を伝えてください。ルーターの型番・ファームウェア・接続方式も確認します。実際のWeb公開URL、OBSパスワード、会話本文は調査資料から除いてください。原因が未確認の段階で、特定の回線方式やルーターの故障とは断定しません。

## 字幕の登録とOBSの応答

字幕のログでは、新規発話と訂正を区別し、現在字幕・前字幕のどちらが変わったかを記録します。「字幕を送信待ちに登録」はアプリ内の保持値の更新です。OBSの成功応答を確認すると、送信時の要求番号を付けて「OBS更新確認」を記録します。

前字幕だけの変更でも、現在字幕の本文が同じまま記録される場合があります。OBS切断中は最新の字幕ペアを保持し、再認証後に送信します。

### OBSの接続・認証・応答待ち

OBSへの接続待ちと、接続後の認証完了待ちはそれぞれ5秒で打ち切ります。字幕更新の応答待ちも5秒です。最初の切断や接続・認証失敗は理由付きで警告し、その後の再接続失敗は1分ごとに件数と最後の理由をまとめます。復旧時とアプリ終了時にも残った件数を記録します。`RECONNECT_MS` の再接続間隔は変わりません。

再認証できたら復旧を記録し、保持している最新字幕と前字幕を再送します。OBSを閉じた後も再接続を続けるため、配信終了後はこのアプリも `Ctrl+C` で終了してください。
