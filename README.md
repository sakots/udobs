# UDトークの会話をOBSに表示する

UDトークで認識した会話を、OBSのテキストソースに字幕として表示するアプリです。WindowsとLinuxで動作します。

```text
UDトークのWeb公開 → このアプリ → OBS WebSocket → OBSテキストソース
```

UDトークのWeb公開ページから、新しく確定した発話を取得します。起動前の過去ログは表示しません。ゆかりねっとコネクターNEOやUDトーク文字入力を用意する必要はありません。

開発にはCodexを使用しています。

## 必要なもの

- Node.js 22以降
- pnpm
- OBS Studio 28以降
- UDトークで「ウェブで公開」を有効にしたトーク

## 初回の準備

### UDトークとOBSを準備する

UDトークの「トークを公開する」画面で「ウェブで公開」を選んでください。発行された `https://live.udtalk.jp/...` のURLを設定に使います。

OBSでは「ツール」→「WebSocketサーバー設定」を開き、サーバーを有効にしてください。ポート番号とパスワードも確認します。通常のポート番号は `4455` です。

続いて、OBSにテキストソースを作成してください。以下の例ではソース名を `字幕` とします。

### アプリの設定を保存する

プロジェクトのフォルダで依存パッケージをインストールしてください。

```bash
pnpm install
```

[.env.example](.env.example)をコピーして、同じフォルダに `.env` を作成します。

WindowsのPowerShellで使うコマンドです。

```powershell
Copy-Item .env.example .env
```

Linuxで使うコマンドです。

```bash
cp .env.example .env
```

`.env` を開き、パスワード、ソース名、Web公開URLを実際の値に置き換えてください。

```dotenv
OBS_PASSWORD="OBSで設定したパスワード"
OBS_INPUT_NAME=字幕
# ひとつ前の字幕も表示する場合に設定
OBS_PREVIOUS_INPUT_NAME=
OBS_URL="ws://127.0.0.1:4455"
UDTALK_PUBLIC_URL="https://live.udtalk.jp/ここに64文字のID"
POLL_MS=500
MAX_CHARS_PER_LINE=24
```

`OBS_INPUT_NAME` にはOBSのソース名、`UDTALK_PUBLIC_URL` には発行されたURLを指定してください。OBSの認証が有効な場合は `OBS_PASSWORD` も必要です。パスワードを引用符で囲むと、`#` や空白を含む値も読み込めます。

OBSが別のPCで動いている場合は、`OBS_URL` の `127.0.0.1` をそのPCのIPアドレスに置き換えます。

### ひとつ前の発話も表示する

OBSにもう1つテキストソースを作り、`字幕_ひとつ前` などの別名を付けてください。その名前を `.env` の `OBS_PREVIOUS_INPUT_NAME` に指定します。

```dotenv
OBS_INPUT_NAME=字幕
OBS_PREVIOUS_INPUT_NAME=字幕_ひとつ前
```

新しい字幕が届くと、直前の字幕をこのソースに表示します。最初の発話では空欄です。不要なら `OBS_PREVIOUS_INPUT_NAME` は空欄のままにしてください。

## 起動と終了

設定を保存したら、プロジェクトのフォルダで起動してください。

```bash
pnpm start
```

次の2行が表示されれば接続完了です。

```text
OBS WebSocketの認証が完了しました。
UDトークWeb公開に接続しました。新しい確定発話をOBSへ転送します。
```

UDトークで話すと、Web公開に届いた確定発話をOBSの字幕として表示します。

終了するにはターミナルで `Ctrl+C` を押してください。Windowsでは `Ctrl+Break` も使えます。設定を変更した場合は、アプリを再起動すると反映されます。

pnpm経由では、中断時に `ELIFECYCLE` と表示されることがあります。pnpmの終了コード表示を避けたい場合は、次のコマンドで起動してください。どちらの起動方法でもTypeScriptをビルドします。

```bash
node scripts/start.mjs
```

## ログの保存

アプリのログは画面に表示すると同時に、プロジェクトの `logs/` フォルダへUTF-8のテキストで保存します。起動ごとに `udobs-日時-プロセスID.log` を作り、起動時に保存先を表示します。各行の日時はUTCです。

字幕本文、接続・切断、警告、エラー、終了処理のログが保存されます。`Ctrl+C` の直前まで保存するため、書き込みはその都度行います。pnpm自身の `ELIFECYCLE` 表示や、アプリ起動前のビルド出力は含まれません。

ログには会話本文や接続先が含まれます。共有する前に内容を確認してください。`logs/` はGitの管理対象外です。ログは自動削除しないので、不要になったファイルは削除してください。

UDトークとの通信に失敗した場合は、初回から処理名、通信開始から失敗までの時間、エラー名・コード・内部原因も記録します。計測には応答本文の受信・解析も含みます。公開URLやセッショントークンは診断ログから伏せます。終了操作による通信中断は失敗として記録しません。

```text
UDトーク通信失敗: 処理=web/pull/webTalkMessage, 経過=5002ms, タイムアウト設定=5000ms, name=TimeoutError, message=The operation was aborted due to timeout
```

`経過` は実際にかかった時間です。`タイムアウト設定` はこのアプリの上限で、通信処理内部の別のタイムアウトや切断により、それより早く失敗する場合もあります。成功した通信ごとのログは出力しません。

失敗時の `接続診断` には、接続先IP、TCP・TLS接続の成立通知と所要時間、接続の再利用、TLSセッション再開、ALPNの結果を記録します。所要時間はソケットの作成を観測してからの時間です。再利用した接続では、最初に接続したときの時間を表示します。診断機能自体は通信方式や待ち時間を変更しません。

成功時の `UDトーク接続診断` は、処理ごとの初回の新規接続・再利用と、失敗後の最初の成功時に出力します。`接続#` が同じなら同じソケットです。接続の再利用とTLSセッション再開は別の情報です。

`TCP=成立` で `TLS=未観測` の場合は、TCP接続後にTLS成立通知を確認できなかったことを示します。`未観測` は失敗の断定ではありません。Node.jsのバージョンや通信方式によって通知が得られない場合もあります。

接続診断には、要求・応答の `Connection` と、応答の `Keep-Alive` の `timeout`・`max` も記録します。応答を受け取ってヘッダーが存在しない場合は `なし`、応答自体を確認できなかった場合は `未観測` です。未知のヘッダー値は伏せ、ヘッダー全体・Cookie・本文・トークンは保存しません。

`UDトークソケット終了` は、通信完了後に接続が閉じた場合も記録します。同じ `接続#` の診断と照合してください。`end` は受信側の終了通知、`finish` は送信側の終了通知、`close.hadError` はエラーを伴う切断だったかを示します。これらだけでは、サーバーとクライアントのどちらが切断の原因だったか断定できません。アプリの終了時には監視を解除します。

通信ライブラリが正常な接続整理に使う `UND_ERR_INFO` でも、`close.hadError=true` になる場合があります。この組み合わせだけで通信障害とは判断せず、HTTP応答と通信失敗ログも合わせて確認してください。

## 字幕の表示を調整する

`.env` の `POLL_MS` で会話を取得する間隔を指定します。テンプレートの設定は `500` ミリ秒です。通信が不安定な場合は `1000` に上げてください。

`MAX_CHARS_PER_LINE` は自動改行する文字数です。通常は `24` を使います。字幕がOBSの表示幅に収まらない場合は `18` などに下げてください。

### 通信が不安定な場合

`UDTALK_REQUEST_TIMEOUT_MS` はUDトークとの通信全体の上限です。既定は `5000` ミリ秒で、接続待ちから本文の受信・解析までを含みます。TCP・TLSの接続処理にも同じ上限を設定し、結果待ちを中断した後に接続ソケットが既定の約10秒まで残ることを防ぎます。タイマーの実行には多少の遅れが生じる場合があります。遅い正常応答も打ち切る可能性があるため、その場合は `10000` などに上げてください。UDトーク専用の通信エージェントを使い、終了時にはそのエージェントも破棄します。OBSや他の通信の設定は変更しません。

会話取得や閲覧セッション作成に連続で失敗すると、再試行までの待ち時間を `POLL_MS`、その2倍、4倍と延ばします。上限は `UDTALK_RETRY_MAX_MS` で、既定は `10000` ミリ秒です。例えば `POLL_MS=1000` なら、失敗後の待ち時間は1秒、2秒、4秒、8秒、10秒となります。通信自体にかかった時間は別です。会話取得が成功すると通常間隔に戻ります。

一時的な通信失敗では取得位置を保持し、同じ位置から再試行します。これらは待ち時間と接続負荷を調整する対策で、回線や取得先の障害自体を直すものではありません。CLIでは `--udtalk-request-timeout-ms` と `--udtalk-retry-max-ms` でも指定できます。前者は1以上、後者は `POLL_MS` 以上の整数を指定してください。

## 制限と公開URLの扱い

パスコード付きのWeb公開ページには対応していません。また、UDトークのWeb公開に届かなかった発話は、このアプリでも取得できません。

Web公開URLを知っている人はトークを閲覧できます。URLやOBSのパスワードを他人に共有しないようにしてください。

`.env` はGitの管理対象外なので、公開URLやパスワードはコミットされません。

実装はTypeScriptです。次のコマンドで `dist/` にコンパイルしてからテストを実行します。

```bash

```
