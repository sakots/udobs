# UDトークの会話をOBSに表示する

UDトークで認識した会話を、OBSのテキストソースに字幕として表示するアプリです。WindowsとLinuxで動作します。

```text
UDトークのWeb公開 → このアプリ → OBS WebSocket → OBSテキストソース
```

UDトークのWeb公開ページから、新しく確定した発話を取得します。起動前の過去ログは表示しません。ゆかりねっとコネクターNEOやUDトーク文字入力を用意する必要はありません。

開発にはCodexを使用しています。

## 必要なもの

- Node.js 22以降
- pnpm
- OBS Studio 28以降
- UDトークで「ウェブで公開」を有効にしたトーク

## 初回の準備

### UDトークとOBSを準備する

UDトークの「トークを公開する」画面で「ウェブで公開」を選んでください。発行された `https://live.udtalk.jp/...` のURLを設定に使います。パスコードを設定した場合は、その値も確認してください。

OBSでは「ツール」→「WebSocketサーバー設定」を開き、サーバーを有効にしてください。ポート番号とパスワードも確認します。通常のポート番号は `4455` です。

続いて、OBSにテキストソースを作成してください。以下の例ではソース名を `字幕` とします。

### アプリの設定を保存する

プロジェクトのフォルダで依存パッケージをインストールしてください。

```bash
pnpm install
```

[.env.example](.env.example)をコピーして、同じフォルダに `.env` を作成します。

WindowsのPowerShellで使うコマンドです。

```powershell
Copy-Item .env.example .env
```

Linuxで使うコマンドです。

```bash
cp .env.example .env
```

`.env` を開き、OBSパスワード、ソース名、Web公開URLを実際の値に置き換えてください。パスコード付きのWeb公開では `UDTALK_PASSCODE` も設定します。

```dotenv
OBS_PASSWORD="OBSで設定したパスワード"
OBS_INPUT_NAME=字幕
# ひとつ前の字幕も表示する場合に設定
OBS_PREVIOUS_INPUT_NAME=
OBS_URL="ws://127.0.0.1:4455"
UDTALK_PUBLIC_URL="https://live.udtalk.jp/ここに64文字のID"
# Web公開にパスコードがある場合だけ設定
UDTALK_PASSCODE=""
POLL_MS=500
UDTALK_REQUEST_TIMEOUT_MS=5000
UDTALK_RETRY_MAX_MS=10000
MAX_CHARS_PER_LINE=24
```

`OBS_INPUT_NAME` にはOBSのソース名、`UDTALK_PUBLIC_URL` には発行されたURLを指定してください。OBSの認証が有効な場合は `OBS_PASSWORD` も必要です。パスワードを引用符で囲むと、`#` や空白を含む値も読み込めます。

`UDTALK_PASSCODE` はWeb公開のパスコードです。パスコードなしの公開では空欄のままにしてください。CLI引数 `--udtalk-passcode <パスコード>` でも指定できますが、シェルの履歴に残さないため `.env` での設定を推奨します。認証に失敗した場合はパスコードを確認して再起動してください。

OBSが別のPCで動いている場合は、`OBS_URL` の `127.0.0.1` をそのPCのIPアドレスに置き換えます。

設定は既定値、環境変数、CLI引数の順で上書きします。起動時には `.env` も読み込みます。CLI引数は環境変数より優先されます。

### 複数のWeb公開をまとめて表示する

`UDTALK_PUBLIC_URL` にURLをカンマ区切りで指定します。1件だけの設定もそのまま使えます。

```dotenv
UDTALK_PUBLIC_URL="https://live.udtalk.jp/1件目の64文字のID,https://live.udtalk.jp/2件目の64文字のID"
```

引用符で囲んだ値の中で改行して並べることもできます。CLIでは `--udtalk-url <URL>` をURLごとに繰り返してください。CLIで1件でも指定すると、環境変数のURL一覧全体を置き換えます。同じ公開IDのURLを重複指定しても接続は1つです。

各URLを同時に取得し、すべての発話を共通の現在字幕・前字幕にまとめます。両方の発話に時刻がある場合は時刻順、それ以外は受信順です。別URLの同じ発話IDは別の発話として扱い、訂正は元の発話だけに反映します。同じ表示内容では前字幕を繰り上げません。

取得位置・重複判定・再接続はURLごとに独立しており、1件の接続失敗で他の取得は止まりません。ログの `[Web公開1]` などの番号は重複を除いた設定順で、公開URLそのものは出しません。終了時はすべての取得を停止します。

`UDTALK_PASSCODE`、取得間隔、タイムアウトは全URL共通です。パスコードなしの公開とパスコード付き公開は混在できますが、異なるパスコードが必要な公開を同時に使う設定には対応していません。


### ひとつ前の発話も表示する

OBSにもう1つテキストソースを作り、`字幕_ひとつ前` などの別名を付けてください。その名前を `.env` の `OBS_PREVIOUS_INPUT_NAME` に指定します。

```dotenv
OBS_INPUT_NAME=字幕
OBS_PREVIOUS_INPUT_NAME=字幕_ひとつ前
```

新しい字幕が届くと、直前の字幕をこのソースに表示します。最初の発話では空欄です。不要なら `OBS_PREVIOUS_INPUT_NAME` は空欄のままにしてください。

## 起動と終了

設定を保存したら、プロジェクトのフォルダで起動してください。

```bash
pnpm start
```

OBSの認証完了と、各URLの接続完了が表示されれば接続完了です。1件の場合の例です。

```text
OBS WebSocketの認証が完了しました。
[Web公開1] UDトークWeb公開に接続しました。新しい確定発話をOBSへ転送します。
```

UDトークで話すと、Web公開に届いた確定発話をOBSの字幕として表示します。

終了するにはターミナルで `Ctrl+C` を押してください。Windowsでは `Ctrl+Break` も使えます。設定を変更した場合は、アプリを再起動すると反映されます。

pnpm経由では、中断時に `ELIFECYCLE` と表示されることがあります。pnpmの終了コード表示を避けたい場合は、次のコマンドで起動してください。どちらの起動方法でもTypeScriptをビルドします。

```bash
node scripts/start.mjs
```

## ログの保存

ログは画面と `logs/udobs-日時-プロセスID.log` に出力します。字幕本文や接続先が含まれるため、共有前に内容を確認してください。ログは自動削除しません。

ログの項目、字幕登録とOBS更新確認の違い、通信障害の調べ方は[トラブルシューティング](docs/troubleshooting.md)を参照してください。

## 字幕の表示を調整する

`.env` の `POLL_MS` で会話の取得が終わってから次の取得までの待ち時間を指定します。テンプレートの設定は `500` ミリ秒で、未設定時の既定値は `1000` ミリ秒です。通信が不安定な場合は `1000` に上げてください。実際の取得周期には通信時間も加わります。

`MAX_CHARS_PER_LINE` は自動改行する文字数です。通常は `24` を使います。字幕がOBSの表示幅に収まらない場合は `18` などに下げてください。

### 通信が不安定な場合

`UDTALK_REQUEST_TIMEOUT_MS` は通信全体の上限で、既定は `5000` ミリ秒です。TCP・TLS接続待ちは最大 `2000` ミリ秒で打ち切ります。連続失敗時は再試行間隔を延ばし、`UDTALK_RETRY_MAX_MS`（既定 `10000` ミリ秒）を上限にします。一時的な取得失敗では取得位置を保持します。

設定を変える前に、[タイムアウトと再試行の設定](docs/troubleshooting.md#タイムアウトと再試行の設定)と[接続タイムアウトの切り分け](docs/troubleshooting.md#接続タイムアウトの切り分け)を確認してください。

## 制限と公開URLの扱い

UDトークのWeb公開に届かなかった発話は、このアプリでも取得できません。

Web公開URLやパスコード、OBSのパスワードを他人に共有しないようにしてください。パスコードなしの公開では、URLを知っている人はトークを閲覧できます。

`.env` はGitの管理対象外なので、公開URLやパスコード、パスワードはコミットされません。
