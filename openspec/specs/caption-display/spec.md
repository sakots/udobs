# caption-display

実装: [caption-history.ts](../../../src/caption-history.ts)、[text-wrap.ts](../../../src/text-wrap.ts)  
テスト: [caption-history.test.ts](../../../test/caption-history.test.ts)、[text-wrap.test.ts](../../../test/text-wrap.test.ts)

## Purpose

字幕の折り返しと発話履歴からの現在字幕・前字幕の選択について、既存実装の振る舞いを定義する。発話の訂正や遅延受信、同じ本文の再受信があっても、表示する字幕の組み合わせと更新の要否を判断できるようにする。

## Requirements

### Requirement: URLをまたいだ字幕履歴

アプリは全URLの発話を共通の履歴に登録し、既存の時刻順・受信順と現在字幕・前字幕の選択規則を適用しなければならない（MUST）。履歴上の発話識別は取得元と発話IDの組み合わせとし、別URLの同じ発話IDを訂正として扱ってはならない（MUST NOT）。

#### Scenario: 別URLで同じ発話IDが届く

- **WHEN** URL AとBから同じ発話IDで異なる本文が届き、その後Aの本文が訂正される
- **THEN** AとBは別の履歴として保持され、訂正はAの本文だけを変更する
- **AND** Bが現在字幕なら、Aの訂正によってBを置き換えない


### Requirement: コードポイント単位の折り返し

字幕整形は MUST Unicodeコードポイント単位で指定文字数を数え、上限を超える行を折り返す。サロゲートペアの途中で分割してはならない。既存のLFおよびCRLFによる行区切りは維持し、出力の区切りはLFとする。これは書記素クラスタ単位の分割を保証するものではない。

#### Scenario: 指定文字数で長い行を分割する

- **WHEN** 「あいうえおかきくけこ」を上限5文字で整形する
- **THEN** 「あいうえお」と「かきくけこ」の2行になる

#### Scenario: サロゲートペアと既存の改行を維持する

- **WHEN** 「😀😀😀\r\nあい」を上限2文字で整形する
- **THEN** 出力は「😀😀」「😀」「あい」の3行となり、各行はLFで区切られる

### Requirement: 句読点と空白を優先する折り返し位置

上限を超える行では MUST 上限位置から上限の65%を切り上げた位置まで逆順に調べ、`、。！？!?` または空白の直後を最初に見つけた場合に折り返し位置とする。該当位置がなければ上限位置で折り返す。折り返し処理を行った行の各出力断片は末尾空白を除去するが、上限以下でそのまま返す行の末尾空白は変更しない。

#### Scenario: 上限付近の句読点を優先する

- **WHEN** 「これはとても、長い字幕のテスト」を上限8文字で整形する
- **THEN** 「これはとても、」の直後で改行する

### Requirement: 発話IDによる訂正と履歴順序

履歴は MUST 発話IDで新規発話と訂正を区別し、既存IDの訂正では本文だけを変更して履歴位置と元の時刻を維持する。新規発話の並べ替えでは、比較する両方の発話に時刻がある場合は時刻順、同時刻なら受信順とし、それ以外の比較は受信順とする。

#### Scenario: 前の発話を訂正する

- **WHEN** 時刻1の発話A、時刻2の発話Bの順に登録後、Aと同じIDの本文を「A訂正」に変更する
- **THEN** 現在字幕はBのまま、前字幕が「A訂正」になる

#### Scenario: 古い発話が遅れて届く

- **WHEN** 時刻2の発話Bの後に時刻1の発話Aを登録する
- **THEN** 現在字幕はB、前字幕はAになる

#### Scenario: 時刻のない発話を訂正する

- **WHEN** 時刻のない発話AとBを登録後、Aと同じIDで訂正を受け取る
- **THEN** Aは新規発話として末尾へ追加されず、現在字幕Bの前字幕として訂正される

### Requirement: 内容の異なる現在字幕と前字幕

履歴は MUST 末尾の本文を現在字幕とし、末尾からさかのぼって現在字幕と本文が異なる最初の発話を前字幕とする。異なる本文がない場合、前字幕は空文字列とする。発話IDが異なっても本文が同じという理由だけで同じ表示を前字幕へ繰り上げてはならない。

#### Scenario: 同じ本文の新規発話が届く

- **WHEN** A、Bの後に別IDで本文Bを登録する
- **THEN** 現在字幕Bと前字幕Aの組み合わせを維持する

#### Scenario: 最初の発話を表示する

- **WHEN** 空の履歴に本文Aの発話を登録する
- **THEN** 現在字幕はA、前字幕は空文字列になる

### Requirement: 表示ペアが変化した場合だけ更新を通知する

履歴更新は MUST 現在字幕と前字幕の組み合わせが前回と異なる場合だけペアを返し、変更通知を行う。通知には新規発話または訂正の区別、および現在字幕・前字幕のどちらが変わったかを含める。表示ペアに影響しない変更では更新値を返さず、通知もしない。

#### Scenario: 表示対象外の古い発話を訂正する

- **WHEN** 時刻順にA、B、Cを登録した後、Aを訂正しても現在字幕Cと前字幕Bが変わらない
- **THEN** 更新値は返されず、変更通知も発生しない

### Requirement: 履歴件数の上限

履歴は MUST 新規発話の追加と並べ替え後に1000件を超えた場合、先頭の1件を除去して最大1000件に保つ。除去済みIDは、その後の更新で既存発話としては扱わない。

#### Scenario: 履歴上限を超える

- **WHEN** 時刻のない異なるIDの発話を1001件、順に登録する
- **THEN** 最初の発話は履歴から除去され、残る1000件から現在字幕と前字幕を選択する
